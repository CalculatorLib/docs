## Do you need a token?

Probably not, at first:

- **REST API** (`/api/...`) — fully public. No authentication of any kind.
- **MCP server** (`/mcp`) — anonymous access is allowed, limited to **60 requests/minute per IP**. A token raises that to **600 requests/minute per user** and unlocks a personal usage log at [calculatorlib.com/account/mcp-logs](https://calculatorlib.com/account/mcp-logs).

Get a token when your agent starts hitting the anonymous ceiling, or when you want per-user attribution of your MCP traffic.

## Create a token

1. Sign in (or create a free account) at [calculatorlib.com](https://calculatorlib.com).
2. Open [**Account → API tokens**](https://calculatorlib.com/account/api-tokens).
3. Create a token and copy it. Tokens look like:

```
clk_a1b2c3d4e5f60718293a4b5c6d7e8f90
```

The `clk_` prefix plus 32 hex characters. The full value is shown once — store it somewhere safe.

## Use a token

The MCP endpoint accepts the token in either of two headers:

<CodeGroup>
```bash Authorization: Bearer
curl -X POST https://calculatorlib.com/mcp \
  -H "Authorization: Bearer clk_YOUR_TOKEN_HERE" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

```bash X-API-Token
curl -X POST https://calculatorlib.com/mcp \
  -H "X-API-Token: clk_YOUR_TOKEN_HERE" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```
</CodeGroup>

In an MCP client config, add the header to the server entry:

```json
{
  "mcpServers": {
    "calculatorlib": {
      "url": "https://calculatorlib.com/mcp",
      "headers": {
        "Authorization": "Bearer clk_YOUR_TOKEN_HERE"
      }
    }
  }
}
```

<Note>
Not every MCP client supports custom headers for remote servers yet. If yours doesn't, just connect anonymously — everything works, only the rate limit differs.
</Note>

## Failure modes

| Situation | Result |
|---|---|
| No token sent | Allowed — anonymous limits apply |
| Malformed or unknown token | `401` with body `{"error": "invalid_token"}` and a `WWW-Authenticate: Bearer realm="mcp"` header |
| Valid token, limit exceeded | `429` with `Retry-After: 60` — see [Rate limits](/rate-limits) |

<Warning>
A **wrong** token is rejected with `401` — it does not fall back to anonymous access. If you configure a token, make sure it's the real one.
</Warning>
